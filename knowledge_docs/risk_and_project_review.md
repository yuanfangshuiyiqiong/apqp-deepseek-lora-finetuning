# 风险评审与项目节点评审

APQP 项目早期应开展风险评审，识别设计、供应商、工艺、设备、人员、进度、质量和客户特殊要求等方面的潜在风险。风险评审的目标不是简单列问题，而是形成可执行的预防措施。

风险清单通常应包含风险描述、影响范围、发生可能性、严重度、风险等级、预防措施、责任人、计划完成时间、实际完成时间和验证结果。

如果风险应对计划中没有责任人和完成时间，风险项就很难被真正关闭。项目经理和质量负责人应在节点评审中跟踪高风险项状态，确认措施是否执行、效果是否验证、是否需要升级处理。

APQP 节点评审应围绕交付物完整性、风险关闭状态、客户要求满足情况、变更影响、供应商准备状态和量产准备情况展开。评审结论应明确是否允许进入下一阶段。

常见节点评审问题包括：文件只完成形式未验证有效性、风险项长期未关闭、客户特殊要求遗漏、控制计划与 PFMEA 不一致、试生产问题未形成纠正措施、责任人不明确和项目计划频繁延期。

当用户询问“项目早期为什么要做风险评审”时，应说明风险评审可以提前识别潜在问题，明确预防措施和责任人，降低后期质量问题、进度延期和客户投诉的可能性。

当用户询问具体项目进度、责任人或延期情况时，知识库只能解释管理要求；实际进度必须来自项目数据库、任务表或人工维护的结构化数据。
